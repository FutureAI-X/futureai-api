## Docker

### 镜像 与 容器

**镜像**是一个只读的模板，打包了程序 + 它需要的运行环境（操作系统基础、依赖库等）。
**容器**是镜像跑起来的一个实例。

类比：镜像是"安装光盘"，容器是"用这张盘装好并正在运行的机器"。
同一个镜像可以同时跑出好几个互不干扰的容器。

我们说的"打镜像"，就是把项目编译好、连同运行环境一起打成这个模板。

### 数据卷（volume）

容器里写的文件，**容器一删就没了**。所以数据库这种需要持久保存的东西，
要把存储目录挂到一个**数据卷**上 —— 它是独立于容器生命周期的存储。

`docker compose down` 不会删数据卷；`docker compose down -v` 会（`-v` = volumes）。

### 端口映射

```yaml
ports:
  - "8080:3001"
```

**左边是宿主机（你的电脑/服务器）的端口，右边是容器内部的端口。**

容器有自己独立的网络环境。容器里的程序监听 `3001`，外面**默认访问不到** ——
必须通过这样一条映射打通。所以写连接字符串时：

- 在宿主机上（比如用 DBeaver 连数据库）→ 用 `localhost:5432`
- 在另一个容器里 → 用**服务名**，比如 `postgres:5432`

这两条路完全不同，混用是最常见的坑。

### 容器网络

容器之间默认**互相看不见**。只有接进同一个网络才能通信。

接进同一个网络后，Docker 会提供一个内置 DNS，让容器可以用**服务名**互相访问 ——
所以 token-hub 的连接串里能直接写 `postgres`，网关能直接写 `token-hub:3001`。

Docker 还会给每个容器分配一个 IP。我们的网关用了**固定 IP** `172.20.0.2`，
因为下游服务要靠这个地址判断"请求是不是网关发来的"（见 `TRUSTED_PROXIES`）。

### Docker Compose

一个 YAML 文件描述"这套服务由哪几个容器组成、怎么配"，然后一条命令全起起来。

一个 compose 文件 = 一个**项目**。项目内的容器自动在同一个默认网络里，
服务名就是彼此的域名。

## 反向代理 与 网关

### 反向代理是什么

客户端以为自己在直接跟某个服务说话，实际上中间隔了一层：

```
浏览器 ──> Nginx ──> 真正的服务
```

Nginx 收到请求后，替客户端去访问后端，再把结果返回。

**为什么需要它**：

- **一个 IP 上跑多个网站** —— 靠域名区分该转给谁（见下）
- **HTTPS 只在这一层做** —— 后端服务不用各自处理证书
- **统一加东西** —— 限流、gzip 压缩、安全响应头、访问日志

我们说的"网关"，就是这个反向代理容器。

### 域名分流

同一台机器的 80/443 端口只能被一个程序占用。但 Nginx 可以在**一个** 443 端口上
同时服务多个域名，靠请求里的域名决定转给谁：

```
token.example.com    ──> token-hub:3001
newapi.example.com   ──> new-api:3000
sub2api.example.com  ──> sub2api:8080
```

这就是"三个服务共用一个网关"。每个域名在 Nginx 配置里对应一个 `server` 块。

### TLS 终止

HTTPS 的加解密在网关这一层做完，转发给后端时用普通 HTTP。
因为后端都在同一台机器的内部网络里，那段链路上没有人能窃听。

术语叫"TLS 终止"。

## HTTPS 与证书

### 证书解决什么问题

HTTPS 的前提是：**浏览器得确认它连的真是你的服务器**，而不是中间有人在冒充。
这个确认靠证书。

流程是：服务器出示证书说"我是 token.example.com"，证书上有一个**签发者**的签名。

### CA 与浏览器的信任列表

浏览器和操作系统里**预装了一份受信任的机构名单**（叫 root CA store），
里面是 DigiCert、GlobalSign 这类机构。签发者在名单里 → 直接放行；不在 → 弹警告。

我们本地测试用的**自签证书**，签发者是它自己：

```
subject = CN=token.example.com
issuer  = CN=token.example.com     ← 自己签自己
```

自己给自己担保，自然不在名单里 → 浏览器报 `ERR_CERT_AUTHORITY_INVALID`。
**这是预期的，不是配错了。**

### Let's Encrypt

一个**免费的证书颁发机构**，2015 年出现。在它之前，拿到一张被信任的证书要花钱、
走人工流程、每年手动续期。它把这三件事一起解决了：免费、全自动、有 API。

现在它是全球最大的 CA。用的协议叫 **ACME**。

### 它怎么确认域名是你的

不能随便给谁签，否则任何人都能申请 `google.com` 的证书。验证方式是：

```
1. 你申请 token.example.com 的证书
2. 它给你一串随机码，要求你放到
   http://token.example.com/.well-known/acme-challenge/<码>
3. 它真的去访问这个地址
4. 拿到了 → 说明你能控制这个域名 → 签发
```

**所以签证书的前提是：域名解析已生效 + 80 端口能从公网访问**（它得连回来）。

网关配置里的 `location /.well-known/acme-challenge/` 就是专门响应这个校验的。

### 有效期只有 90 天

刻意的设计。所以要挂**自动续期**，否则三个月后网站突然打不开。
我们的 `certbot.sh renew` + cron 就是干这个的。

## DNS

### 域名怎么变成 IP

你在浏览器输入 `token.example.com`，机器得先知道它对应哪个 IP ——
这个查询过程叫 DNS 解析。

### A 记录

在域名服务商的控制台里配置的一条规则，含义是"这个域名指向哪个 IPv4 地址"：

| 类型 | 主机记录 | 值 |
|---|---|---|
| A | token | 1.2.3.4 |

主机记录填 `token`，配合域名 `example.com` 就是 `token.example.com`。

### 为什么"解析生效"需要等

这条记录要同步到全球的 DNS 服务器，各家缓存策略不同，可能几分钟到几小时。
没生效就去签证书会失败，因为验证服务器找不到你的机器。

验证：`ping -c 1 token.example.com`，看返回的 IP 对不对。

## 为什么 80 和 443 是特殊端口

浏览器里输入 `http://example.com` 时，实际访问的是 80 端口；
`https://example.com` 是 443 端口。协议默认端口，不用写出来。

所以**只要你想让外面的人用浏览器访问，就绕不开这两个端口** ——
一台机器上它们只能被一个程序占用。这正是我们需要网关的原因。

## SNI

一个 IP 上托管多个 HTTPS 网站，服务器怎么知道该出示哪张证书？

**TLS 握手时，客户端会告诉服务器它想访问的域名** —— 这个字段叫 SNI
（Server Name Indication）。Nginx 靠它决定用哪个 `server` 块。

⚠️ **客户端连接的是 IP 地址时，通常不发 SNI**（SNI 的设计就是填域名）。
所以：

```bash
# 这样不行：curl 连 127.0.0.1，不发 SNI，nginx 不知道该用哪个 server
curl -k -H "Host: token.example.com" https://127.0.0.1/health

# 这样可以：--resolve 让 curl 认为域名就是 token.example.com，
# SNI 和 Host 都对了
curl -k --resolve token.example.com:443:127.0.0.1 https://token.example.com/health
```

这就是文档里反复强调"必须用 `--resolve`"的原因。

## 环境变量 与 .env

程序运行时从**环境变量**读取配置（数据库地址、密钥等），而不是写死在代码里。
好处是同一份代码/镜像，换个环境变量就能换个部署。

`.env` 文件是一堆 `键=值`，Docker Compose 会自动读取它。这个文件**不进版本控制**
（里面有密钥）。

## cron

Linux 上的定时任务。`crontab -e` 编辑当前用户的任务列表，每行一条。
开头五个字段表示"什么时候执行"：

```
17  3  *  *  *     要执行的命令
│   │  │  │  └── 星期几（* = 每天）
│   │  │  └───── 月  （* = 每月）
│   │  └──────── 日  （* = 每天）
│   └─────────── 时  （3 点）
└─────────────── 分  （17 分）
```

上面这行读作"每天凌晨 3:17"。
