# 计费规则

查询接口见 [查询计费规则](get-pricing.md)。本文说明计费公式与积分精度。

## 1 计费公式

单个模型的积分规则由管理端配置，计算公式为：

```text
本次总积分 = 基础积分（或命中的参数组合积分）+ 参考图张数 × 每张参考图积分
```

基础积分可以为 0，表示免费模型。参考图附加计费只对图片生成类端点（`/v1/images/generations`、`/v1/images/edits`）生效，按请求体中标准字段 `image_urls` 的图片张数叠加扣除。`每张参考图积分 = 0` 等同于不开启。数组中重复的 URL 只计一次，单次计费张数上限为 100。

参数组合条件只能引用标准请求字段：`model`、`prompt`、`size`、`resolution`，且值必须为字符串。匹配前平台会对 `size` 做小写归一化、对 `resolution` 做大写归一化，因此条件值建议使用 `resolution=2K`。匹配时大小写不敏感，历史小写规则仍可命中。数组字段 `image_urls` 永远命中不了条件，因此不能用参数组合实现参考图计费。

管理端保存规则时会校验 `param_path` 必须是上述字段之一，否则返回 400 并列出可选值。

## 2 积分的小数位

积分的业务精度为 3 位小数，由 `model.CreditPrecision` 定义。规则录入、计费、管理员调整用户积分与界面展示均按此口径。

`/v1/*` 接口不接受金额参数，积分由平台按模型规则算出，因此该约束只影响管理端。配置积分规则、调整用户积分时，超过 3 位小数返回 400。界面向下取整展示，因此显示出的积分一定可以花费。

数据库列的标度为 `numeric(20,10)`，宽于业务口径。放宽到 4 位只需修改 `CreditPrecision` 与前端的 `CREDIT_DECIMALS`，无需改动 schema，也无需订正数据。
