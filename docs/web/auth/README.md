# 登录与认证

登录接口见 [登录](login.md)。本文说明登录后的令牌、`data_key` 与限流规则。

## 1 data_key

`data_key` 是当次会话的 AES-GCM 密钥，base64 编码的 32 字节。它用于解密接口返回的加密字段，例如供应商 API Key 和一次性展示的完整 API Key。

需要读取这类字段时，通过 `X-Data-Key` 请求头携带 `data_key`，不要放进查询串。

## 2 JWT 与登录态

`token` 是 JWT，24 小时过期。修改密码后，无论用户自助修改还是管理员重置，该用户已签发的所有令牌都会立即作废，客户端需要重新登录。

## 3 API Key 的可见性

API Key 本身不以明文入库。`api_keys` 表里只有它的 SHA-256 与用于展示的前后缀。因此 `GET /api/user/tokens` 只返回 `key_prefix`、`key_suffix` 与 `key_length`，不返回完整 key，也不需要 `X-Data-Key`。

展示时按 `key_length` 把中间垫成等长，形如 `sk-a1b2c3***********************xy9z`，总长与真实 key 一致。完整 key 只在创建时的那次响应里出现一次，之后无法再取回。

## 4 登录限流

登录接口有防爆破限流。同一来源 5 分钟内失败 5 次即返回 429，成功登录会清零计数。计数按来源 IP 统计，因此 `TRUSTED_PROXIES` 必须配置正确，否则所有用户会被算作同一来源，一人触发即锁定全站登录。
