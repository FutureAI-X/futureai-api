# 环境变量说明

本文件是 `.env` / `.env.example` 中所有配置项的完整说明。env 文件本身只保留
`KEY=VALUE`，不再写注释；需要查某项的含义、默认值或注意事项时看这里。

## 文件与用法

| 文件 | 用途 |
|---|---|
| `.env.example`（仓库根目录） | 宿主机直跑，或本地 docker compose |
| `.env`（仓库根目录） | 本地实际配置，由上一份复制而来 |
| `deploy/futureai-api/.env.example` | 生产容器部署，在部署目录下复制为 `.env` |

```bash
cp .env.example .env
chmod 600 .env
```

`.env` 与一切 `.env.*` 副本都已被 gitignore，且含密钥，不要提交。

两份模板对应两种运行环境，**不要互相复制**。生产那份与根目录那份的差异只有四处：

1. 生产不含 `PORT` / `SQL_DSN` / `TRUSTED_PROXIES`：容器内网络视图与宿主机不同，
   这三项由 `docker-compose.yml` 按容器网络生成并覆盖。
2. 生产多 `GATEWAY_IP`：仅用于生成容器内的 `TRUSTED_PROXIES`。
3. 两份都有 `FUTUREAI_API_TAG`，但要求不同：根目录模板默认 `latest`，只影响本地开发栈；
   生产必须填具体标签，且 compose 会拒绝空值。
4. 生产显式给出 `POSTGRES_USER` / `POSTGRES_DB`，根目录那份依赖 compose 的默认值。

其余各项（密钥、连接池、限流、计费、对象存储）两份含义一致。

## 服务

### `PORT`

- **作用**：HTTP 服务监听端口。
- **默认**：`3001`。
- **说明**：本地 compose 把容器端口映射到宿主机 `8080`，因此容器与本机直跑可以同时开着。
- **注意**：只对本机直跑生效；两份 compose 都把容器内端口写死为 `3001`。生产模板不含此项。

### `GIN_MODE`

- **作用**：Gin 框架运行模式。
- **默认**：`release`。
- **说明**：取值 `debug` / `release`；只有 `debug` 会开启调试模式，其余值一律按 release 处理。
- **注意**：生产必须 `release`。debug 会打印每个请求的详细日志，性能也更差。

### `DEBUG`

- **作用**：是否打印 SQL 日志。
- **默认**：`false`。
- **说明**：取值 `true` / `false`；开启后由 GORM 输出实际执行的语句。
- **注意**：仅用于本地排查。生产开启会把 SQL 语句连同参数写进日志。

## 安全密钥

### `JWT_SECRET`

- **作用**：签发与校验登录 Token 的 JWT 签名密钥。
- **必填**：是，至少 32 字符。
- **生成**：`openssl rand -hex 32`。
- **注意**：
  - 留空、过短或沿用示例值都会让服务拒绝启动（fail-closed）。
  - 换掉这个值会让所有已签发的 Token 立即失效，用户需重新登录。

### `SECRET_KEY`

- **作用**：加密数据库中的供应商 API Key 等敏感字段。
- **必填**：是，至少 32 字符。
- **生成**：`openssl rand -hex 32`。
- **注意**：
  - 一旦用于加密数据后不可更改：改了，已存的供应商密钥全部解不开，且无法恢复。
  - 请另抄一份存到密码管理器——丢失等于所有供应商密钥永久不可用。

### `INITIAL_ROOT_PASSWORD`

- **作用**：首次启动时创建的 root 管理员密码。
- **默认**：无。仅在 `users` 表为空时生效。
- **说明**：留空时程序随机生成，并写入工作目录的 `root_initial_password.txt`（权限 `0600`）。
- **注意**：
  - **容器部署必须设置**，不要依赖自动生成：生成的文件会随容器重建消失，而库里的
    root 用户还在，之后就再也拿不到初始密码。
  - 含 `$` 必须用单引号包起来，如 `'a$b$c'`；双引号仍会被展开成空串，登录时会一直提示密码错。
  - 无论哪种方式，登录后请立即修改。

## 数据库

### `POSTGRES_USER`

- **作用**：数据库用户名，postgres 容器、备份脚本与 `SQL_DSN` 共用。
- **默认**：`futureai_api`。
- **注意**：
  - 只在数据卷首次初始化时生效：数据卷已存在时改这里不会改动库里的角色，反而会让应用连不上。
  - 必须写在 `SQL_DSN` 上方（根目录模板）。

### `POSTGRES_DB`

- **作用**：数据库名，postgres 容器、备份脚本与 `SQL_DSN` 共用。
- **默认**：`futureai_api`。
- **注意**：
  - 只在数据卷首次初始化时生效：数据卷已存在时改这里不会改动库名。
  - 必须写在 `SQL_DSN` 上方（根目录模板）。

### `POSTGRES_PASSWORD`

- **作用**：数据库密码。postgres 容器用它初始化数据卷；compose 用它拼出应用的 `SQL_DSN`。
- **默认**：无；留空时 compose 会拒绝启动。
- **生成**：`openssl rand -hex 24`。
- **注意**：
  - 只在数据卷首次初始化时写进数据库。初始化之后再改，应用就连不上已有数据了——
    那时需要进容器用 `ALTER USER` 改。
  - 根目录模板：必须写在 `SQL_DSN` 上方。godotenv 只展开位于引用行上方的变量，
    写反了不报错，只会把密码展开成空串。
  - 根目录模板：只能用 hex / base64url。该值被原样拼进连接串，`@ : / #` 会把它拆坏。
  - 生产模板：不要用 `# $ " ' \` 和空格。尤其是 `$`：compose 插值会把它当变量引用，
    展开失败是静默的（变成空串），最后表现为密码认证失败。

### `SQL_DSN`

- **作用**：PostgreSQL 连接字符串。
- **默认**：`postgres://${POSTGRES_USER}:${POSTGRES_PASSWORD}@localhost:5432/${POSTGRES_DB}?sslmode=disable`
- **说明**：
  - 格式 `postgres://用户名:密码@主机:端口/数据库名?sslmode=disable`。
  - 用户名、密码、库名分别引用上面的三项，改其中任一项都只需改一处。
  - 本机直跑填 `localhost:5432`；容器内由 compose 覆盖为服务名 `postgres`。
- **注意**：
  - 变量名只认 `[A-Z0-9_]`：写成 `${postgres_password}` 不会被展开，也不报错，只会得到空密码。
  - 指向的库若不是 compose 建的那个，要么把它的账号密码设成上面三项，要么把这条改回明文写死。
  - 生产模板不含此项。

### `SQL_MAX_IDLE_CONNS`

- **作用**：连接池允许保持的最大空闲连接数。
- **默认**：`10`。
- **注意**：空闲连接会一直占着数据库侧的后端进程；配得比 `SQL_MAX_OPEN_CONNS` 大没有意义。

### `SQL_MAX_OPEN_CONNS`

- **作用**：连接池同时打开的最大连接数。
- **默认**：`80`。
- **注意**：别配到 `100`。PostgreSQL 默认 `max_connections=100` 且为超级用户留了几条，
  打满时会被数据库拒绝连接。

### `SQL_MAX_LIFETIME`

- **作用**：连接的最长存活时间（秒），到期归还即被关闭。
- **默认**：`1800`。
- **注意**：配得太短（如 `60`）等于让整个连接池每分钟重建一遍。PostgreSQL 每个连接都是
  独立后端进程，重建要 fork 加认证往返，还占着可观的常驻内存。

### `SQL_MAX_IDLE_TIME`

- **作用**：空闲连接的最长存活时间（秒）。
- **默认**：`600`。
- **注意**：
  - 只限寿命不限空闲的话，低峰期攒下的空闲连接会一直占着数据库侧进程，直到寿命到期。
  - 配 `0` 或负数表示不因空闲而关闭连接。

## 网络

### `TRUSTED_PROXIES`

- **作用**：告诉应用「哪些地址是我们自己的代理」。只有当 TCP 对端落在列出的网段内时，
  应用才会读取 `X-Forwarded-For` 里的客户端 IP；否则一律按 TCP 对端地址算。
- **默认**：空（谁的代理头都不信，最安全）。
- **说明**：
  - 逗号分隔的 IP 或 CIDR，如 `172.20.0.2/32,10.0.0.0/8`。
  - 本机直跑和本地 compose 前面都没有代理，保持留空即可。
  - 生产模板不含此项：deploy 的 compose 会按 `GATEWAY_IP` 自动生成并覆盖。
- **注意**：
  - 用到客户端 IP 的地方有两处：登录防爆破限流，以及公开文件读取接口的 IP 限流。
  - 部署在代理之后却留空时，所有请求的来源都会被算成网关那一个 IP。登录限流会把全体
    用户当成同一个人——攻击者发 5 次错密码就能让全站 5 分钟内无法登录；公开文件接口
    也会让全站共享同一份额度。
  - 切勿填 `0.0.0.0/0`：那等于信任一切，客户端自带的 `X-Forwarded-For` 重新变得可伪造。

### `GATEWAY_IP`

- **作用**：网关容器在共享网络 `gateway-proxy` 上的固定 IP。compose 用它拼出应用容器的
  `TRUSTED_PROXIES`（形如 `172.20.0.2/32`）。
- **默认**：`172.20.0.2`。
- **说明**：
  - 实际地址由 `deploy/gateway/docker-compose.yml` 的 `ipv4_address` 决定，两处必须一致。
  - `/32` 表示只信任这一个地址，而不是整个网段。
- **注意**：
  - 只有改了网关固定 IP 时才需要动这里，且必须两处同步改。不一致时应用会把请求来源算错，
    登录限流可能把全体用户当成同一个人。
  - 变量名刻意不叫 `TRUSTED_PROXIES`：compose 会用部署目录的 `.env` 做插值，若照抄宿主机
    那份（`127.0.0.1/32`），应用会认不出网关。
  - 仅生产模板包含此项。

### `OUTBOUND_PROXY`

- **作用**：必须经代理才能访问供应商 API 时，出站请求走的代理。
- **默认**：空（直连）。
- **说明**：形如 `http://10.0.0.1:3128`，支持 http/https/socks5。
- **注意**：
  - 刻意不复用 `HTTP_PROXY` / `HTTPS_PROXY`：环境里意外存在的代理变量会让所有出站流量
    （含随请求发出的供应商 API Key）静默改道。
  - 启用后目标地址不再逐 IP 校验（拨号终点变成代理本身），请确保代理侧有出网管控。

## 接口与限流

### `API_RATE_LIMIT_PER_MINUTE`

- **作用**：`/v1` 接口按用户维度的限流速率（令牌桶）。
- **默认**：`60`。
- **说明**：单位次/分钟；在 API Key 校验之后生效，因此按用户计而不是按 IP。
- **注意**：限流用来约束上游额度消耗，这些端点每次调用都真实花费供应商配额。

### `API_RATE_LIMIT_BURST`

- **作用**：限流允许的瞬时突发量（令牌桶容量）。
- **默认**：`10`。
- **注意**：配得远大于每分钟速率时，单用户在短时间内可发出的请求数会明显超过
  `API_RATE_LIMIT_PER_MINUTE`。

### `UPLOAD_CREDITS`

- **作用**：图片上传接口单次扣除的积分。
- **默认**：`0`（免费）。
- **说明**：端点 `/v1/uploads/images`。
- **注意**：
  - 上传是拿平台自己的供应商密钥把用户文件转存到上游，存储与带宽成本全部由平台承担。
  - 保持 `0` 又不限速时，任何持有效 API Key 的用户（哪怕余额为 0）都能以每分钟 60 次的
    速率持续消耗。
  - 配置非法（负数、非数字）时按 `0` 处理并打错误日志，不会拒绝启动。

### `IMAGE_GET_RATE_LIMIT_PER_MINUTE`

- **作用**：`GET /v1/images/get/:file_id`（公开文件读取）按来源 IP 的限流速率。
- **默认**：`1000`。
- **说明**：单位次/分钟；令牌桶突发量按速率的 1/6 计算，最少 10。
- **注意**：
  - 该端点无需认证，IP 是唯一可用的限流维度，因此 `TRUSTED_PROXIES` / `GATEWAY_IP` 必须
    配置正确，否则所有请求会共享同一份额度。
  - 配置非法（负数、非数字）时按默认值 `1000` 处理，不会拒绝启动。

## 对外地址

### `PUBLIC_BASE_URL`

- **作用**：对外访问地址，用于把文件 ID 拼成可直接访问的完整 URL。
- **默认**：根目录模板 `http://localhost:3001`；生产模板 `https://futureaiapi.com`。
- **说明**：
  - 填协议 + 域名；也可只写裸域名，按 `https` 处理。
  - 生产必须与网关域名一致。
- **注意**：
  - 未配置或配置非法时，任务响应中的 `url` 回落到上游原始地址（`url_vendor`）。
  - 改网关域名时这里必须同步改，否则返回的文件地址不可访问。

## 对象存储

### `TENCENT_COS_BUCKET_URL`

- **作用**：成图转存使用的对象存储桶域名。
- **默认**：空（不启用转存）。
- **格式**：`https://examplebucket-1250000000.cos.ap-guangzhou.myqcloud.com`。
- **注意**：在腾讯云主机内，桶域名通常解析到 `169.254.0.0/16`（链路本地）走内网直连。
  对象存储客户端对此专门放行，属于正常现象；若日志出现「拒绝连接内网或保留地址
  169.254.0.x」，说明请求走错了出站客户端，不是腾讯云侧的问题。

### `TENCENT_COS_SECRET_ID` / `TENCENT_COS_SECRET_KEY`

- **作用**：访问 COS 的子账号密钥。
- **默认**：空（不启用转存）。
- **注意**：
  - 建议使用子账号密钥，只授予该桶的**上传、读取与删除**权限（过期对象由应用清理，
    需要 `DeleteObject`）。
  - 默认按私有桶工作：读取接口用服务端预签名临时地址，不依赖匿名读权限。
  - 三项都配置后才启用转存；缺任意一项时任务照常完成，只是不写 `file_id`。
  - 长期凭证，泄露后可直接读写桶内对象，不要提交到仓库。

## 文件生命周期

### `FILE_TTL_SECONDS`

- **作用**：转存文件的有效期（秒）。
- **默认**：`86400`（24 小时）。
- **说明**：写入 `files.ttl_seconds` 与 `files.expires_at`。
- **注意**：
  - 到期后公开读取接口返回 `410`；对象由清理任务删除。
  - 配置非法（非数字、`<=0`）时按 `86400` 处理并打错误日志。

### `FILE_CLEANUP_ENABLED`

- **作用**：是否启用过期文件清理。
- **默认**：`true`。
- **注意**：关闭后过期对象不会被删除，存储用量会持续增长。

### `FILE_CLEANUP_INTERVAL_SECONDS`

- **作用**：两轮清理之间的间隔（秒）。
- **默认**：`600`。

### `FILE_CLEANUP_BATCH_SIZE`

- **作用**：每轮处理上限（条）。
- **默认**：`1000`。
- **说明**：对象删除与记录回收各自计算，即一轮最多删 1000 个对象、回收 1000 条记录。

### `FILE_CLEANUP_GRACE_SECONDS`

- **作用**：过期后延迟多久才删除对象（秒）。
- **默认**：`900`。
- **说明**：避开仍在进行中的读取代理，避免把正在流式转发的对象删掉。

### `FILE_CLEANUP_RETENTION_SECONDS`

- **作用**：对象删除后，`files` 记录再保留多久（秒）。
- **默认**：`604800`（7 天）。
- **说明**：保留期内读取接口继续返回 `410`；期满后记录被删除，再访问返回 `404`。

### `FILE_CLEANUP_RETRY_WINDOW_SECONDS`

- **作用**：对象删除失败后的最长重试窗口（秒）。
- **默认**：`604800`（7 天）。
- **注意**：超过窗口仍失败的记录不再重试，对象会残留在桶里，通过日志暴露。

清理任务只以 `files` 表为准，不会列出桶来对账。上传成功但没落库的孤儿对象由上传路径
做补偿删除；进程在上传与落库之间被杀死的情况不在覆盖范围内。

## 镜像

### `FUTUREAI_API_TAG`

- **作用**：应用容器使用的镜像标签，决定运行哪个版本。
- **默认**：
  - 根目录模板：`latest`（仅本地开发栈使用，`go run` 不读这一项）。
  - 生产模板：**刻意留空**，必须填具体标签（如 `20260915225600`）。
- **说明**：
  - 由 `./deploy/build-image.sh` 打出。
  - 升级与回滚都是改这一行，改完 `docker compose up -d`。
- **注意**：
  - 生产不能预填 `latest`：compose 的守卫只拒绝空值，`latest` 会被放行，而每次
    `docker load` 都会静默指向新版本，回滚时根本说不清服务器上跑的是哪一版。
  - 升级前务必先备份数据库：应用启动会跑 AutoMigrate，部分变更不可逆，回滚旧镜像
    不一定能回到旧 schema。
